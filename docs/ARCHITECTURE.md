# Architecture

How the game is put together, for anyone changing the code. Rules and point values
as the player sees them are in `README.md`; this file is about the *implementation*.
Line references are approximate — search for the function name.

## Configuration
All numbers that shape gameplay live in `CONFIG` (`js/config.js`), grouped as `layout`,
`spawn`, `waves`, `scoring`, `input`, `combat`, `powerups`, `perks`, `kick`. Formulas below
show the default values; the code reads them as `CONFIG.<group>.<key>`. `BASE_MODS` in
`js/perks.js` copies the perk-adjustable ones at the start of each run.

## Assets & sound
- Paths are conventional (`spritePaths(kind, id, poses)` in `js/data/asset-manifest.js`);
  `ASSET_FILES` (generated by `tools/build-assets.mjs`) lists which files actually exist,
  and nothing outside it is ever requested.
- `js/assets.js`: `preloadImages(onLoad)` (called once by main.js; `onLoad` re-renders the
  how-to roster) creates an Image per listed sprite; `getSprite(def, pose)` returns it once
  loaded (fallback pose → `walk` → `ready`), else `null` → emoji circle is drawn.
- Full-body sprites: when a sprite exists, `drawEnemy`/`drawFleeing` draw it without the
  circle, height `rpx(r) × CONFIG.sprites.heightMul` (2.8), feet at `y + rpx(r) × feetOffset`,
  mirrored by `e.facing` (sign of horizontal velocity; art faces right). Poses: `walk`,
  `idle` while frozen, `kicked` while fleeing. Hit flash uses `ctx.filter = brightness(2.2)`.
- `js/audio.js`: `play(id, arg)` uses the decoded file from `SOUNDS[id].file` if loaded,
  otherwise the synth function named by `SOUNDS[id].synth`. `preloadSounds()` runs after
  the first user gesture (`unlockAudio`). `sfx.*` are thin wrappers around `play`.
- `SOUNDS` ids: `enemy_<id>` (catch reaction, synth `catch` pitched by combo), `hero_<id>`
  (kick impact, synth `kick`), and the game sounds of `docs/prompts/sound-design.md` §3 (hit,
  miss, catch, combo, close, power, freeze, wall, shield, sweep, wave, cleared, warn, boss,
  leak, perk, over, record, tap), each with a synth fallback. `warn` is rate-limited
  (`CONFIG.waves.warnThrottle`).
- Music: `playMusic('menu'|'game'|'boss')` / `stopMusic()` with looping `<audio>` elements,
  only for files in the manifest; `CONFIG.audio.musicVolume`; mute pauses it. main.js plays
  `menu` on menu screens, `game` while playing (`boss` while the tier-1 character is on
  screen, switched from `onHud`), and stops on game over.

## Module graph

```
index.html ──loads──> js/main.js (UI glue)
                         ├── js/lasso.js (LassoGame extends Game: Rope 'Em! mode)
                         ├── js/game.js (engine: Game class)
                         │      ├── js/map.js        (geometry + map data)
                         │      ├── js/config.js     (CONFIG: all tunables)
                         │      ├── js/data/enemies.js (roster/balance data)
                         │      ├── js/assets.js     (sprites → data/heroes.js)
                         │      ├── js/perks.js      (upgrades + BASE_MODS)
                         │      ├── js/audio.js      (sfx/play → data/sounds.js)
                         │      └── js/i18n.js       (t, fmt)
                         ├── js/data/enemies.js (to build how-to tables)
                         ├── js/perks.js      (emoji/max for the upgrade screen)
                         ├── js/audio.js      (unlock, mute)
                         └── js/i18n.js       (language switch)
sw.js  — registered by main.js on load (not on file://)
```

`game.js` never touches the DOM except its canvas. It talks to the UI only through
three **hooks** passed to the constructor by `main.js`:

| Hook | Called | Used for |
|---|---|---|
| `onHud(game)` | every frame | score, wave, combo, shields, sweep meter (main.js caches last values to avoid DOM churn) |
| `onBanner(title, sub)` | wave start / wave clear | big centered banner text |
| `onGameOver(summary)` | 1.1 s after a tier-1 breach | game-over screen, high score save |
| `onPerks(ids)` | after the break following every `PERK_EVERY`-th wave | shows the upgrade screen; main.js calls `game.choosePerk(id)` |

## Game modes
There are two **play modes**, each a `Game` instance on the same canvas (`main.js`
`games = { classic, lasso }`). Only the one with `active = true` updates, draws and takes
input; `setMode(m)` switches, sets `body[data-mode]` (CSS hides `.lassoOnly` / `#sweepBtn`),
and saves `kto-mode`. `window.__game` is always the active one.
- **classic** = `Game` (`js/game.js`): this whole document unless stated otherwise.
- **lasso** ("Rope 'Em!") = `LassoGame extends Game` (`js/lasso.js`), see
  "Rope 'Em! mode" below and `docs/PLAN-lasso.md`.

Override points in `Game` that the lasso mode uses: `updateEffects(dt)` (cosmetics, all
modes) / `updatePlay(dt)` (simulation), `nextWave()`, `spawn()`, `spawnPoint()`,
`breach()`, `onPointer()`, `useSweep()`, `wavePool(n)`, `powerupKinds()`, `leakLabel()`,
`stealthAlpha(e)`, `drawLayer(t)` (after kicks), `drawHint(t)`, `drawBossBar()`,
`summary()`. `e.pose` (optional) overrides the sprite pose in `drawEnemy`.

`Game.hero` is the chosen hero id (`HEROES`), set by `start(heroId)`.
`Game.mode` is one of `'menu' | 'playing' | 'paused' | 'perk' | 'over'`
(`'perk'` = simulation stopped while the upgrade screen is open).
- The render loop (`loop` → `update` → `render` → `onHud`) **always runs**, including
  on the menu (the map is the menu background).
- `update()` animates particles/floaters in every mode but only simulates when
  `mode === 'playing'`.
- `main.js` owns screen visibility (`show(id)`, `id = null` means in-game).
  Pause is triggered by button, `P`/`Esc`, or `visibilitychange`.

## Coordinate system
- Map data is lon/lat; `proj(lon, lat)` (map.js) is an equirectangular projection to
  **map units**: `x = (lon − 88) · cos 24°`, `y = 26.8 − lat` (y grows down).
  **1 map unit ≈ 100 km.** All gameplay distances/speeds/radii are in map units.
- `Game.resize()` fits the Bangladesh bounding box plus `PAD` (0.7 units of India) into
  the window between HUD insets (`insets.top = 64`, `insets.bottom = 90` px), giving
  scale `s` and offsets `ox, oy`. Convert with `sx(x)`, `sy(y)`; `rpx(r)` converts a
  radius with a 15 px minimum so things stay tappable on phones.
- `this.view` is the visible rectangle in map units, used to clamp spawns on screen.
- Particles and floaters are stored in **screen pixels**, enemies/power-ups in map units.

## Map data (`js/map.js`)
- Source: Natural Earth 10m Admin-0 countries (public domain). `tools/build-map.mjs`
  takes Bangladesh's mainland ring (~1830 pts), tags every vertex by the edge that starts
  there (`I` India / `M` Myanmar / `C` coast: within 0.0015° of that neighbour's outline),
  simplifies each same-tag run separately with Douglas–Peucker (0.02 map units ≈ 2 km, so
  tag boundaries stay exact) → ~340 pts, plus the 15 biggest islands and neighbour land.
  Output: `js/data/map-bd.js` (generated, committed). Re-run:
  `node tools/build-map.mjs <ne_10m_admin_0_countries.geojson> [--tolerance 0.02] [--preview out.svg]`.
- Neighbour land (`INDIA_LAND`, `MYANMAR_LAND`, `OTHER_LAND` = Nepal/Bhutan/China) is
  clipped to lon 78–102 / lat 14–32 (Sutherland–Hodgman) and simplified at 0.05.
- `map.js` projects that data; `MAINLAND` vertices are clockwise from the northern tip.
  Exports used by the engine: `BD`, `INDIA_EDGES`/`INDIA_LEN` (spawn edges), `INDIA` and
  `OTHER_LAND` (arrays of rings), `MYANMAR`, `ISLANDS` (drawing only), `DHAKA`, `LABELS`,
  `BBOX`. `SEA` is still exported but unused.
- Rendering: canvas filled with the sea gradient, then land shapes (each also stroked in its
  own colour to hide hairline gaps between separately simplified countries), then BD + islands.
- Exports: `BD` (projected polygon), `INDIA_EDGES` (`{a, b, len}`), `INDIA_LEN`,
  `SEA` and `MYANMAR` polygons (for drawing and to reject spawns), `DHAKA`, `LABELS`,
  `BBOX`, `pointInPoly`, `distToPoly`.
- Paths are rebuilt as `Path2D` in `buildPaths()` on every resize.

## Wave lifecycle (`game.js`)
1. `start()` → `reset()` → `nextWave()`.
2. `nextWave()` builds `this.queue` of character IDs:
   - `count = 5 + floor(1.8·n)`
   - pool = all tier>1 characters with `unlock ≤ n`, weights: `small1` = 10, other
     tier 3 = `2 + 0.6n`, tier 2 = `1 + 0.35n` (`weighted()` picks).
   - If `isMainWave(n)` (every 3rd, every 2nd from 12), `MAIN_ID` is inserted mid-queue.
   - `spawnInterval = max(0.3, 1.5·0.92^(n−1))`, `speedMul = min(2.1, 1 + 0.07(n−1))`.
3. `update()` pops the queue every `spawnInterval·rand(0.7,1.3)`; from wave 6 a 20%
   chance of a second pop in the same tick. A pop calls `warn(type)`, which picks the
   spawn point immediately and stores `{type, p, t: WARN_TIME}` in `this.warnings`
   (drawn by `drawWarning`); after 0.7 s it becomes `spawn(type, p, true)`.
4. When the queue is empty **and** no enemies **and** no pending warnings remain →
   `waveCleared()` adds bonuses and sets `breakT = 2.4` s; when it runs out →
   `afterBreak()`: on every `PERK_EVERY` (2nd) wave it sets `mode = 'perk'` and calls
   `onPerks(perkOptions(game, 3))`; `choosePerk(id)` applies it and calls `nextWave()`.
   Otherwise `nextWave()` directly.

## Spawning
- `spawnPoint()`: pick a random point along `INDIA_EDGES` (length-weighted), push it
  outward along the edge normal by `SPAWN_MIN..SPAWN_MAX` (0.5–0.8 units), clamp to
  the visible view, reject unless it's inside one of the `INDIA` rings, outside BD and
  ≥ 0.3 from the border.
  40 tries, else `null` (spawn skipped). Returns spawn `x,y` and border target `tx,ty`
  (slightly inside the border).
- `spawn(type, at?, primary = !at)`: creates the enemy object. If `primary`, speed is
  scaled by a **fairness factor** `clamp(dist/SPAWN_NOMINAL, 0.5, 1)` so clamped spawns
  on narrow phones aren't unfairly close. Tier 1 gets `+5 HP × mainCount`.
  `def.group > 1` spawns extra pack members around the first (primary spawns only).
  Wave spawns are primary (via warnings); summons and splits are not.
- Summoners (`def.summons = { every, types }`) spawn helpers near themselves with an
  `at` point; interval shrinks `0.05 s` per wave, min 1.8 s.
- Splitters (`def.splits = { into, n }`): `catch()` → `split(e)` spawns `n` of `into`
  side by side, 0.1 units further from the border. Not triggered by Sweep.

### Enemy object
```js
{ type, def, x, y, tx, ty, phase /*0 = to border, 1 = to Dhaka*/,
  hp, maxHp, r, speed, t, seed, hitFlash, summonT, home: {x, y}, near /*dist to border*/ }
```
Movement: head to `(tx,ty)`; within 0.03 switch `phase = 1` and head to `DHAKA`.
`wobble` adds a sinusoidal sideways component. A breach is detected by
`pointInPoly(BD, x, y)` every frame → `breach(e)`.

## Heroes, kicks and fleeing
- Menu ▶ PLAY → `#heroSelect` (main.js `renderHeroes`), choice saved in `kto-hero`;
  "Play again" reuses it. `game.start(heroId)`.
- Every successful hit calls `spawnKick(e, heroId, quiet)`: pushes `{hero, x, y, dirX, dirY, t, life}`
  to `this.kicks` (screen px), placed behind the intruder (against the flee direction) by
  `rpx(r) + CONFIG.kick.heroOffsetPx`, and plays the hero's sound (`HEROES[id].sound || 'kick'`).
  `drawKick`: `ready` pose for `windupTime`, then `kick`; emoji + 🦶 fallback; mirrored when
  `dirX < 0` (art faces right); pop-in and fade.
- Flee direction `fleeVector(e)`: from the border target `(tx,ty)` to the spawn `home`
  (outward, back to India).
- On a catch the intruder leaves `this.enemies` (can't be tapped, can't breach, doesn't
  block wave-clear) and joins `this.fleeing` (screen px) moving at `fleeSpeedPx` until it
  has travelled `fleeDistancePx` (300), fading out, with a hop, wobble, dust and the
  `kicked` pose. Kicks and fleeing animate in every mode except `paused`/`perk`.
- Non-final hits: knockback/dash as before + kick + small hop (`e.hop`).
- Sweep: kick visuals cycle through all heroes (`CONFIG.kick.sweepAllHeroes`); sounds are
  suppressed per intruder (one `sweep` sound instead).
- Reaction sound on a catch: `play(e.def.sound)` if set, else the pitched `catch` synth.

## Input & scoring
- `onPointer` (pointerdown on canvas): power-ups first (30 px radius, doesn't count as
  a tap), else nearest enemy within `max(rpx(r)·1.25, 26)` px. Miss → combo reset,
  ripple. Hit → `damage(e, 1)`.
- `damage()`: if HP remains → knockback 0.035 units away from the border target;
  `dash` characters also jump 0.16 sideways (flipped if that lands inside BD).
  HP ≤ 0 → `catch()`.
- `catch()`: combo (`COMBO_WINDOW` 1.5 s), `multiplier() = min(5, 1 + floor((combo−1)/5))`,
  points × mult (sweep: 50%, no mult, no close-call, no sweep gain, no power-up drop),
  close call `+25` if `distToPoly < CLOSE_CALL (0.12)`, sweep meter `+def.sweepGain`,
  power-up drop chance `POWERUP_CHANCE + mods.dropBonus` (100% for tier 1).
- `comboLeft()` (0..1) drives the HUD combo timer bar.
- `useSweep()`: needs `sweep ≥ 100`; deals 99 damage to everyone, 4 to tier 1.
- `breach()`: tier 2/3 → remove, subtract `penaltyOf(def)` (floored at score 0), combo
  reset. Tier 1 → if `shield > 0`, consume one and teleport her to `home`; else
  `mode = 'over'` and call `onGameOver` after 1.1 s.
- Stats: `this.stats` (whole run) and `this.waveStats` (for per-wave accuracy/leak bonuses).
  `summary()` builds the object passed to `onGameOver`.

## Perks / run modifiers (`js/perks.js`)
`game.mods` is reset to `BASE_MODS` each run; gameplay code reads these instead of
constants: `tapRadius` (× hit radius), `knockback` (× 0.035 push), `sweepGain`
(× def.sweepGain), `dropBonus` (+ drop chance), `comboWindow` (s), `freezeTime`,
`wallTime` (s). `game.perks` counts picks per id (for `max` and the `n/max` label).
`perkOptions()` shuffles the perks that are under `max` and pass `available(game)`.

## Power-ups
`POWERUPS` in `js/data/enemies.js` holds emoji/colour only; effects are hard-coded in
`Game.collect()`: freeze → `freezeT = mods.freezeTime` (4), wall → `wallT = mods.wallTime` (7; speed × 0.4), shield →
`+1` up to `MAX_SHIELD` (3; not dropped when full), charge → sweep `+40`. Power-ups
live 6 s and blink in the last 1.5 s. Adding a power-up = entry in `POWERUPS` + branch
in `collect()` + `pu.*`, `puName.*`, `puDesc.*` strings.

## Rope 'Em! mode (`js/lasso.js`)
Tunables: `CONFIG.lasso`. `wave` is the **round** number.
- **Patrol loop** `PATROL` (module level): the BD mainland resampled to `pathPoints`, pushed
  `pathInset` inside along each edge normal, smoothed (`pathSmooth`). The hero has an arc
  position `heroS` and direction `heroDir` (`reverse()`, ⇄ button / `R`), runs one lap per
  `heroLapTime`, and stands still while `rope` is not null.
- **Rounds**: `nextWave()` sets `target`, `roundT`, the spawn rate and `speedMul`, and maybe
  schedules Hasina (`mainAt`). `endRound()` at time 0 → bonus + `breakTime` break, or
  `gameOver('target')`. `targetLeft` = time left when the target was reached (time bonus).
- **Characters**: spawned at random points inside BD (via `warn()` → `spawnPoint()`), up to
  a cap. `state`: `lurk` (random waypoints, never leaves BD) → `bolt` (to the nearest India
  border point + overshoot) → escape when outside BD (`breach`: penalty, or game over /
  shield for Hasina). `roped` while on the rope; `dash` after the rope snaps. `near` is
  only set while bolting/dashing (danger ring, border glow). Hasina uses `mainSpeed`.
- **Rope** `{ phase: 'out' | 'back' | 'reel', x, y, tx, ty, target, cx, cy, auto, tug, autoT }`
  in map units. `out` flies at `ropeSpeed` to the tap (clamped to `ropeRange`), `landLoop()`
  picks the nearest catchable character within `loopRadius` (stealth alpha ≥ 0.5; dodgers
  may hop out). 1-HP characters auto-reel (`autoReelTime`); others have a tug meter that
  taps raise (`reelPerTap / strength`) and the character lowers (`pullBase × strength`/s),
  with strength = `hp^strengthExp` (× `mainPullMul` for Hasina). Meter ≥ 1 → `ropeCatch()`;
  ≤ 0 → `snap()`.
- **Scoring**: points × combo multiplier (Hasina `mainPoints`), `roundBonus × round` +
  `timeBonusPerSec × targetLeft`. Escapes cost the tier penalty (`stats.leaked` = escaped).
- Drawing (`drawLayer`): dashed patrol loop, rope (quadratic curve with sag) and loop
  ellipse, tug meter + "TAP TAP!", the hero (sprite poses `run`/`throw`/`pull`/`cheer`
  if present in the manifest, else `ready`/`kick`; emoji disc fallback), range ring.

## Rendering order (`render()`)
India background → Myanmar → sea gradient → labels → Bangladesh fill + red flag disc
(clipped) → border outline (India border glows mint / pulses red when any enemy is
within `DANGER`, orange & thick while wall is active) → Dhaka dot + label → power-ups →
spawn warnings (`drawWarning`) → fleeing intruders (`drawFleeing`) → enemies (`drawEnemy`: danger ring, tier-1 gold aura, shadow, body/sprite/emoji, frozen
tint, HP bar if maxHp>1, name tag for tier ≤ 2) → kicks → `drawLayer` (mode extras) →
`drawHint` (first-catch "TAP!" hint) → breach
marker → particles → floaters → full-screen overlays (freeze tint, sweep flash, leak
flash, `drawBossBar` (gold HP bar under the HUD while tier 1 is alive), red vignette
when tier 1 is near the border). Hero kicks (`drawKick`) are drawn right after the enemies. Screen shake translates the
whole frame. DPR is capped at 2.

Map labels come from `LABELS[].key` → `t('map.<key>')`, so they follow the language.

## i18n
`t('a.b', {var})` walks nested keys in the current language, falls back to `en`, then
to the key. Values can be arrays (e.g. `rules`). Numeric vars are formatted with `fmt`,
which converts digits to Bangla in `bn`. `applyLang()` in main.js re-renders every
`[data-i18n]` element (via `innerHTML`, so strings may contain markup) plus the
generated how-to tables and game-over stats.

## PWA
- `sw.js`: precaches `ASSETS` on install under cache name `VERSION`, deletes other
  caches on activate, serves same-origin GETs stale-while-revalidate.
- Manifest: fullscreen, any orientation, icons in `icons/`.
- `main.js` shows an "Install app" button on `beforeinstallprompt`, and an iOS
  "Add to Home Screen" hint on iOS Safari when not standalone.
